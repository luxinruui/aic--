# 电脑端启动诊断修复 v0.1.1

用户报告：双击启动后，按任意键窗口关闭，之后没有看到预览；未观察到可提供的错误信息。当前没有用户本机的 Python/安装/GUI 错误输出，不能断言具体原因。

## 已确认的可诊断性问题

旧入口只检查 `.venv` 中是否有 Python 文件，不能判断依赖是否装完整；调用安装脚本失败后，安装脚本暂停一次，返回上层后就退出。安装和程序输出没有持久保存，因此按键关窗后无法追查。

独立 `setup_preview.cmd` 原本只安装、不启动 GUI；用户尚未确认当时执行的是哪个入口，不能把“误点安装入口”当作已确认原因。

## 修复

- 新增共享启动引导程序：寻找受支持的 64 位 Python、检查项目环境和固定依赖、必要时修复依赖、自动打开预览；已有可用环境跳过安装。
- 默认 Python 太新时寻找电脑已装的 Python 3.10～3.12，包括常见 `robot_vision` 环境；不兼容的旧项目环境保留，另建独立环境。
- 四阶段进度即时显示；Python 子进程的输出、错误和退出码写入 `logs/startup/latest.log`，保留上一份为 `previous.log`。
- 原生 CMD 在 Python 启动前就显示标题并创建 `launcher.log`；失败时提示日志位置并停留，不依赖安装脚本的暂停。
- 新增 `diagnose_preview.cmd`，通过 `cmd /k` 在程序退出后仍保留命令窗口。
- 启动日志纳入一键 Git 同步范围；ZIP 用户可直接提交文本日志用于诊断。

## 验证边界

新增覆盖 Python 选择、旧环境保留、跳过重复安装、输出/错误持久保存、安装异常、退出码传播及日志轮换的回归测试。另增加 Windows 专用的真实 CMD 检查，覆盖空格目录启动与失败返回；云端 Linux 不把这两项跳过检查算作 Windows 验证通过。

本轮实际执行39项测试：37项通过，2项 Windows CMD 检查因 Linux 环境跳过。新版引导通过已有项目环境启动8帧无窗口演示，确认跳过重复安装、四阶段提示、程序输出和退出码落盘；记录见 `logs/verification/startup_bootstrap_smoke.log` 与 `startup_fix_tests.txt`。Python 3.10 语法和五个 CMD 的 ASCII/CRLF 检查通过。

用户电脑仍需用新版诊断入口重试，或从文件夹打开 CMD 运行旧入口并提供最后输出，才能确定本次没有出现窗口的实际原因。
