# 2026-11-16：电脑端手势预览 v0.1.0

用户要求开始电脑端工作，并将项目代码和日志同步到 `luxinruui/aic--`。

## 本次交付

- 新增独立电脑端程序、Windows 双击启动/安装入口，默认单关节左肘预览，也支持双手六轴。
- 支持摄像头编号、显示镜像、左右手标记修正、可选控制范围标定、暂停和重启。
- 掌心上下映射肩抬，左右位置映射合拢，拇指食指距离与掌宽之比映射肘角；单关节模式统一使用掌心上下。
- 独立识别线程只保留最新一帧。无效、过期、重复或时间不递增的观测不生成有效目标；无目标以空值记录，不冒充零度。
- 数值/事件日志自动保存，提供 Git 同步脚本；同步范围仅运行日志和标定设置，原始图像/视频不保存。
- 提供合成演示源、GUI 实际窗口检查脚本和 GitHub Actions 工作流。

## 实现决定

设计阶段推荐 Tasks Hand Landmarker。实际首版改用 MediaPipe 0.10.21 的 `solutions.hands` 完整模型：官方 Python 安装包内已包含手掌检测和手部关键点模型，避免运行时再下载模型；新建项目 `.venv`，不改变原 `robot_vision` 环境。

模型推理使用未镜像输入，按该版本 Hands API 的自拍镜像假设修正左右标签；镜像仅用于画面显示。另保留手动交换左右标记选项，以适配相机驱动自身的镜像情况。

当前仓库尚未取得原 `backpack_arms6` 的完整控制源码，因此交付范围为电脑预览与目标计算，没有加入串口或机器人网络输出。已有机器人标定数值没有被本程序修改。

## 实际验证结果

完整记录见 [verification](../verification/)。

- **28 项测试通过**，覆盖映射端点、范围限制、不同图像宽高比例、左右身份不确定、无效点、丢手、过期/重复采样、平滑、日志和运行生命周期。
- 真实 CPU 流式模型通过模拟摄像头输入处理一张空白图；摄像头打开失败路径能报告原因并释放设备。模拟输入不代表真实摄像头或真人识别验证。
- 两个内置模型文件存在且已记录 SHA256，独立空白图推理通过；依赖 `pip check` 通过。
- **180 帧六轴合成运行**完成：右臂每轴 180 帧有效；演示主动隐藏左手 15 帧，左臂每轴 165 帧有效，失效期间数值为空。CSV 以约 10Hz 抽样，记录 53 行。该记录的 0ms 推理时间来自合成源，不能作为模型性能数据。
- 真实 Tk GUI 检查通过：单关节/六轴切换、禁止演示标定、保存配置、暂停清空、重启建立独立日志。
- 中文布局截图在系统 Python 3.13 / Tk 8.6 的纯演示 GUI 下生成并目视检查；项目 Python 3.12 / Tk 9 另做 GUI 功能检查。识别模型使用项目固定依赖和 Python 3.12，不宣称支持 Python 3.13 安装当前模型依赖。
- Windows x64 / CPython 3.10 依赖的二进制包解析成功；这不是本次在真实 Windows 上运行程序的证据。
- Python 源码通过 Python 3.10 语法检查；四个 Windows CMD 为 ASCII + CRLF。日志同步测试使用本地临时 Git 仓库与本地 bare 仓库，不访问用户仓库。

## 待电脑现场验收

1. 更新仓库后双击 `run_preview.cmd`，先确认真实相机能打开。
2. 使用自己的左手检查默认左肘目标，并确认左右标记；再分别验证双手六轴。
3. 观察光照、遮挡、实际推理耗时和摄像头帧率；按需保存个人控制范围标定。
4. 结束预览后运行 `sync_github.cmd` 上传该次真实相机数值日志。
