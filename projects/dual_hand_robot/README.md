# 双手机器人联控 · 独立项目 v1.0

左手控制底盘，右手五指控制六个上肢舵机。拇指联动双大臂，其余四指按“左肘、左肩｜右肩、右肘”分配。电脑端、背包接收端、协议、日志和离线包均在本目录独立保存。

本项目从底盘已验收版本 `681e10295bc56d7816d46e33420df715ac036320` 派生，旧 `projects/left_hand_chassis` 和旧入口不作为本项目发布内容修改。新服务使用 **TCP8770**、应用标识 `aic-dual-hand-robot/1`，不混用旧底盘8768、六轴8765或统一控制8767。

2026-11-17已通过NoMachine完成现场部署，电脑与背包TCP8770及真实UART的OFF检查通过。当前用户尚未设置上肢基准，接收端保持基准未确认、全系统暂停，未进行本项目实机动作验收。现场路径和运行方法见 [本机运行说明](RUN_THIS_ROBOT.md)，通用导入步骤见 [NoMachine导入说明](README_NOMACHINE.md)。

## 电脑端

解压电脑包，双击 **`run_robot.cmd`**，点击“连接背包…”，输入背包IPv4和8770端口。电脑需要64位Python3.10～3.12，依赖沿用原环境；启动脚本可只读复用已匹配的 `LEFT_HAND_PYTHON` 或 `.local-python.txt`，不覆盖原robot_vision环境。

只看本地软件目标仍可使用 `run_dual_hand.cmd`。机器人联控使用 `run_robot.cmd`，不可用旧项目的窗口连接新接收端。

1. 打开摄像头，确认绿骨架Left是自己的左手，蓝骨架Right是右手。
2. 右手分别采集①自然半握起始位、②握拳、③展开；支持选择单根手指补采。联合控制时，另完成左手原有三步校准。
3. 选择仅上肢、仅底盘或双手联合，点击启用。已连接背包的上肢需要匹配背包的**软件参考姿态**，而不是自动跳到①自然半握对应目标。
4. 首次背包参考为原工程基准：双肘伸直、双肩侧平举、双大臂展开；在默认映射下，通常需要右手五指展开并保持0.5秒。匹配提示会指出需调整的手指。
5. 空格、Esc或暂停统一撤销输出；丢手、旧采样、失焦、断网或串口错误也会暂停。重新连接或恢复数据后仍需手动启用。

右腕倾斜不控制上肢；左手保留原握拳前进、展开后退和倾斜转向。实机连接禁止合成演示，网络线程也会独立拒绝demo来源。

| 右手输入 | 关节 | ID |
| --- | --- | --- |
| 拇指收拢 / 张开 | 双大臂合拢 / 展开 | 3、33 |
| 食指弯曲 / 伸直 | 左肘 | 1 |
| 中指弯曲 / 伸直 | 左肩放低 / 抬起 | 4 |
| 无名指弯曲 / 伸直 | 右肩放低 / 抬起 | 34 |
| 小指弯曲 / 伸直 | 右肘 | 31 |

默认手势范围：肘弯曲量0～120°、肩抬臂0～90°、大臂合拢0～60°。范围窗口可以禁用单个独立关节，双大臂始终作为一组；连接机器人时两侧大臂必须给出相同语义合拢角。开始小范围单轴联调时可仅启用左肘，将其范围设为0～20°。

## 原AIC执行链路的复用

六轴实测数据取自AIC《连接人体识别数据与机器人动作》的 `backpack_arms6/arm_config.json` 历史文件读取结果；原始参数完整保存在本目录 `arm_config.json`，来源及厂商基准报文见 [参考证据](docs/reference/aic_six_axis_evidence.json)。

旧工程的肘角是内角：180°伸直、0°折叠。新手指输入使用“弯曲量”，因此执行层明确转换 `旧肘角 = 180 - 弯曲量`，再查原三点曲线。肩抬臂与合拢沿用原0～90°定义，不直接将手势数值写成舵机原始位置。

上肢采用原设备07、命令5F、22字节载荷、little-endian 11个uint16字段：

```text
ID1, ID2, ID3, ID4, 腰20, 腰21, ID31, ID32, ID33, ID34, 时长
```

腰20/21使用原零值保持；ID2/32首次上肢运动时按原值2048设置，之后用零值保持。未启用的动态关节同样发送零值保持，不将它们拉回初始位置。

保持原上肢20Hz、50ms短轨迹、最大1200原始位置单位/秒和4800单位/秒²。双大臂按共同语义进度推进，并依据两侧实测曲线中较严格的速度/加速度约束限速。

底盘保持平移上限20、旋转上限60、加速度40/120、150ms有限时长指令；实机窗口默认前后强度35%、旋转100%。它们是原厂控制量，不是物理速度。

背包只有一个Bus打开 `/dev/ttyS0`、115200/8E1并使用Linux exclusive；底盘停止优先于上肢更新。短写、串口异常锁定FAULT并关闭端口，不重发运动报文。旧接收端占用UART时，新硬件模式会报错退出，不自动杀进程或移除独占保护。

## 启用与暂停

每个连接先确认OFF，再使用新的启用代次提交零底盘和匹配上肢参考的准备帧，收到READY后才提交活动目标。改变模式、输入会话或活动关节需先暂停。新连接不自动恢复原ON状态。

背包保留原底盘独立20Hz看门狗、150ms链路检查和原始采样300ms寿命；重复摄像头帧不能改变目标或延长原始采样寿命。PC窗口快照超过150ms时，网络线程自行发送OFF。

上肢启动前必须人工设置并确认原工程基准；程序不读取实际舵机位置，不自动归位。硬件接收端不加 `--confirm-arm-baseline` 时，即使UART已打开也拒绝上肢使能。该参数表示操作者已按导入说明核对和设置基准，不应在尚未设置时填写。

暂停时底盘发送STOP，上肢停止追加轨迹，不回零或释放力矩；已下发的50ms上肢轨迹可能完成，ACK和软件目标不代表机械到位。当前没有新增经过实测的整机碰撞包络，联合姿态和机械停止效果需要现场逐项验证。

## 日志、构建与验证

- 电脑：`logs/runs/`，原底盘CSV、上肢CSV、校准、连接和状态事件；不保存相机影像。
- 背包：`logs/backpack/*.jsonl`，接收状态、软件目标位置、UART写入计数、上肢短段计数、暂停原因。
- 本次检查：`logs/verification/`，软件测试和未部署状态分开记录；不把FakeSerial或回环TCP当作实机验收。
- 原有 `runtime/latest_upper_preview.json` 在新联控窗口中会标明实际连接模式，字段仍为上位机目标，不是舵机回读。

在新分支的Git克隆中可运行 `python scripts/sync_logs.py`，只提交本目录数值/事件日志；若当前是main或旧分支会拒绝执行。ZIP副本不具备Git历史，日志先保存在本地。

```sh
python -m unittest discover -s tests -v
python3 -S run_backpack.py --self-test
python3 -S run_backpack.py --check-deps
python scripts/gui_robot_smoke.py
python scripts/gui_upper_smoke.py
python scripts/build_packages.py
```

GUI检查需要图形会话。背包接收端和离线依赖支持Python3.8；电脑识别支持Python3.10～3.12。背包默认预览不导入OpenCV、MediaPipe、Tk或pySerial；显式 `--drive` 才打开UART。

源码和日志只写独立分支 `dual-hand-robot-20261117` 的新目录。本次没有推送或合并到原main，也没有更新旧底盘目录。生成的ZIP在本次对话本地交付，不上传GitHub；从源码可运行构建脚本生成相同用途的离线包，CI只检查构建，不上传二进制构建产物。
