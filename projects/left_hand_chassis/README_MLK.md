# 米联客板卡：控制转发与本地启停 v1.2

按用户确认，板卡承担控制转发和本地启停。程序运行在米联客板卡的ARM Linux用户态，电脑继续识别左手，智慧背包继续负责机器人UART。

两条路线均保留：

```text
直接：电脑 → TCP8768 → 智慧背包 → UART → 底盘
板卡：电脑 → TCP8769 → 米联客转发/启停 → TCP8768 → 智慧背包 → UART → 底盘
```

板卡端无需摄像头、MediaPipe、pySerial或Python第三方包；需要Linux和Python3.8以上。此版不要求修改FPGA位流。板卡Linux/Python/网络/按键驱动的实际可用性必须先上板确认，不能因USB端口存在就认为已部署成功。

## 已完成的软件与当前板卡状态

- 已实现双跳TCP、本地启停、原始采样年龄和帧号传递、独立超时检查、断线封锁旧ON、可选Linux输入事件适配，以及只读按键探测工具。
- 主机上15项板端模块检查通过，含真实双跳回环TCP和模拟执行端；没有在米联客板上运行这些测试，也没有真实机器人运动验证。
- 用户已连接FS01板卡。2026-11-16本机再次识别CH342-A COM12、CH342-B COM19及FTDI通道；COM12/115200/8N1接收与单次回车查询均无输出，尚未确认Linux控制台。已请用户在监听时按K7捕获启动日志；不能据无输出判板卡损坏。
- 前期FS01记录存在DDR配置/启动镜像疑点，尚未完成Linux恢复。当前代码准备不会覆盖原镜像、写TF/Flash或执行DDR/JTAG恢复。

## 上板后先检查的五项

| 项目 | 需要看到的证据 | 当前不能假定的能力 |
|---|---|---|
| Linux启动 | 完整启动日志并进入可交互终端 | 仅有COM口不表示Linux已启动 |
| Python运行时 | `python3 --version`至少3.8，`--check-runtime`通过 | FS01 Buildroot镜像是否包含Python尚未确认 |
| IP网络 | 板卡能连智慧背包，电脑能连板卡8769 | 现有Type-C连接是CH342/JTAG，不是已接通的USB网卡 |
| 本地启停 | 控制台a/s/q可用；需要实体键时测出eventN和键码 | 不猜测K1/K2/K3的GPIO、寄存器或键码 |
| 实机执行 | 低速四方向、叠加旋转、两段断线停止 | 回环测试不表示机械方向/制动时延通过 |

当前软件可以先用电脑直连背包部署，板卡路线在上述条件具备后插入。用户当前仅有USB连接，不把购买网线、网卡或显示器作为编写和离线验证的前提；TCP板卡路线实际运行时仍需要已验证可用的板端IP链路。

## 复制与启动

板卡专用包为 `left_hand_chassis_mlk_v1_2_20261116.zip`，解压目录 `aic_mlk_relay/`。它与通过NoMachine导入机器人的背包包是两个独立目录；板卡需要在Linux可用后，通过已验证的文件复制方式（如TF文件复制或可用网络上的scp）另行拷入。

先在板端目录检查，不连接任何机器人：

```bash
python3 -S run_mlk_relay.py --check-runtime
python3 -S run_mlk_relay.py --self-test
```

若Python不存在或版本太旧，先记录镜像/CPU架构/根文件系统情况，再用匹配FS01的环境补齐运行时；本包不包含伪装成板端运行时的Windows Python，也不自动安装系统包或改写启动镜像。

1. 智慧背包先按 [背包说明](README_BACKPACK.md) 启动PREVIEW。
2. 板卡运行（将示例IP替换为背包当前实际IPv4）：

   ```bash
   python3 -u run_mlk_relay.py --backpack 172.20.10.3
   ```

3. 等待板卡日志显示下游连接，板卡默认本地停止。板卡终端输入 **a并回车**，允许本地转发；它本身不会使机器人运动。
4. 电脑运行 `run_robot.cmd`，连接目标改为**板卡IPv4、8769端口**。显示“板卡/背包预览”或“板卡/实机”后，回主窗口完成校准并手动启用。
5. 板卡终端 **s并回车** 立即撤销本地允许并向下游发OFF；**q并回车** 退出。**r并回车** 重新连接背包，之后两端都要重新启用。

新连接、板卡重启、上游异常、下游断开或本地停止后，旧电脑ON不能恢复运动。普通电脑手动暂停可以保持板卡本地允许，但仍要求电脑OFF/新代次启用。PC断开连接会撤销板卡本地允许。

三处 `robot_config.json` 保持相同。数据包保留原始输入会话、帧号和采样年龄；中继不会把旧识别结果当成新采样。两段链路延迟都会计入300ms新鲜度预算，网络慢时可能安全暂停，需要现场测量。

## 实体按键：先探测，再配置

默认控制台启停已经实现。若板上按键由Linux input子系统提供，先只读查看：

```bash
python3 -S board_input_probe.py
python3 -S board_input_probe.py --device /dev/input/event0 --seconds 15
```

`event0`只是命令格式示例，必须按第一条输出选择真实设备。按下目标按键，记录 `type=1 code=N value=1`。K7是板卡电源重启键，不作为本程序的软件停止键。

确认输入设备和两个不同键码后才运行：

```text
python3 -u run_mlk_relay.py --backpack 背包IPv4 --input-device 已确认的event路径 --arm-keycode 已确认键码 --stop-keycode 已确认键码
```

程序只读input事件，忽略释放和自动重复；同批次停止优先。输入设备断开会停止并拒绝再启用，需修复后重启。若内核未暴露板载按键为input事件，先继续控制台模式，再根据实际设备树/驱动补适配，不直接试写GPIO/MMIO地址。

Linux也支持SIGUSR1允许、SIGUSR2停止、SIGTERM退出，供后续明确的本地控制器接入；信号仅排入主循环，不在信号处理器内操作网络锁。所有停止是软件控制停止，实际制动效果仍需现场验收。

板卡日志在 `logs/mlk/`，可以后续拷回Git项目提交。当前包没有设置开机自启，也没有改系统服务或网络配置。
