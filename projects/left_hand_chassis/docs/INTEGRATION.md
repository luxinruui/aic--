# 控制接口与接入约定

本模块独立生成软件意图，后续可将摄像头输入、控制状态机和机器人发送器接入同一进程。

```python
from left_hand_drive.core import Controller

controller = Controller()
# 启动后采集本次三个参照，构造 Calibration，再调用 set_calibration。
# 用户手动启用后调用 enable()；必须先稳定回到静止位。
command = controller.update(new_observation, now_monotonic)
# 没有新帧也必须独立以约20Hz检查；重复旧帧不能代替新采样。
command = controller.tick(now_monotonic, focused=True)
payload = command.as_dict()
```

`Observation` 的来源、采样时间、帧号由采集端提供。真实数据来源为 `camera`，合成输入为 `demo`；切换来源必须重新校准。识别使用镜像输入并固定坐标约定：画面向左倾斜对应正 `yaw_left`。更换识别后端必须重新确认左右手与倾角符号。

## 输出字段

| 字段 | 含义 |
|---|---|
| schema | 固定 `left-hand-chassis/1` |
| session / seq | 进程会话ID / 单调递增输出序号 |
| produced_at | 电脑进程单调时钟秒；不能直接与另一设备的单调时钟比较 |
| valid_for_ms | 默认150ms，超过有效期停止；禁止永久使用最后一个非零值 |
| enabled / input_valid | 明确启用且输入有效，才允许使用非零目标 |
| source | `camera` / `demo` / `none`；接入实机时必须拒绝 `demo` |
| frame_id / sample_age_ms | 原始输入帧号及该帧年龄；发送新快照不代表得到新摄像头帧 |
| forward | [-1,1]，前进为正、后退为负；无左右平移输出 |
| yaw_left | [-1,1]，左转为正、右转为负；与前后独立组合 |
| gesture / roll_delta_deg / reason | 当前手势、相对本次零点的倾角、状态原因 |

`runtime/latest_command.json` 是电脑本地原子替换的预览快照。未来跨设备传输应复用原TCP会话/序号/采样年龄机制；背包还需独立超时停车。不要把它当成已经接通的机器人网络协议。同设备读取者应检查会话、序号、单调时间以及明确有效期，文件损坏或更新中断时立即清零。

接现有模式0底盘编码器时，可将正前进映射为方向0°、负前进映射180°，速度取绝对值并乘现场验证后的最大值；左转符号与原 `Q` 键一致。具体最大速度、加速度限制、通信和停止帧应由最终集成控制器负责，首次实机需低速检查方向。

## 校准与手势逻辑

四根手指使用 MCP到指尖直线距离 / 逐节路径长度；拇指使用拇指尖到小指掌根距离 / 掌宽。均从考虑宽高比例的像素坐标计算。

每次运行采集自然半握、握拳、展开三个参照。端点差异不足、采样不连续、姿态不稳或静止位重合时拒绝校准。五根手指都接近握拳端点才前进，都接近展开端点才后退；单根手指不符时归为静止/过渡手势，前后清零。进入移动手势需持续180ms，离开即停止前后输出。

旋转角取手腕到四个掌根平均位置的朝向，避免指尖开合直接改变旋转。相对校准零点进行环形角差、60ms时间常数的平滑、10°死区及40°饱和。绝对偏转超过75°解除启用。它测量画面内倾斜，不测手腕向内/外翻的三维旋转。

依靠单目关键点，掌面侧转、遮挡和手指重叠仍可能误判。当前阶段保留校准质量检查、掌面投影大小检查和失效停止；实际手势可分性及左右对应仍要通过真人摄像头验证。
